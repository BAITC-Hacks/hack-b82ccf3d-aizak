Конкурсный проект команды AIZAK для HackAlem, задача **«Умный подбор подрядчиков (#79-lite)»**.
Официальный репозиторий: [BAITC-Hacks/hack-b82ccf3d-aizak](https://github.com/BAITC-Hacks/hack-b82ccf3d-aizak).

Проверено на Windows, Python 3.12.14, Streamlit 1.55.0:

Реальная форма и карточки проверены в браузере для `found`, `none_match`, `no_category`.

## Проблема, аудитория и ценность

Заказчик уже получил каталог подрядчиков по своему городу. Ему нужно выбрать
подходящего исполнителя с учётом даты, бюджета и формата мероприятия и понять,
почему конкретный профиль попал в рекомендации.

Сервис предназначен для частных заказчиков и организаторов мероприятий в Казахстане.
Он возвращает до трёх карточек из существующего каталога и объясняет ограничения
выбора, включая занятость и отсутствие подходящих кандидатов.

## Требования и пользовательский сценарий

1. Выбрать город, дату, формат мероприятия, категорию и бюджет в тенге.
2. При необходимости указать язык и длительность. В форме 0 часов означает
   отсутствие ограничения и передаётся backend как `None`.
3. Нажать «Подобрать». Сервис проверяет ввод, фильтрует каталог и показывает до
   трёх карточек: имя, город, категория, цена «от» и конкретные причины соответствия.
4. Если подходящих меньше трёх, увидеть фактическое количество и объяснение.
5. Изменить дату или другие условия и выполнить новый поиск. Подпись над
   карточками показывает параметры последнего выполненного запроса.

Три исхода различаются явно:

| Статус | Значение |
| --- | --- |
| `found` | Найдено от одного до трёх подходящих кандидатов |
| `no_category` | В каталоге выбранного города нет этой категории |
| `none_match` | Категория есть, но все кандидаты исключены по условиям |

Занятые исполнители и площадки исключаются одинаково. Бронирование, заявки и
уведомления подрядчикам в MVP не входят. Конкурсный ориентир времени ответа —
до 10 секунд; инфраструктурных или производственных гарантий MVP не предоставляет.

## Данные

В приложении используется **`data/hackathon-dataset-anonymized.csv`** из backend-ветки:
66 профилей, из них 13 помечены `synthetic`. Файл не заменялся тестовыми данными.
Массивы в CSV разделены символом `|`; loader преобразует их в списки, цены и часы —
в числа, признаки происхождения — в boolean. Проверяются обязательные поля,
даты и уникальность `id`. Также поддерживается официальный JSONL-формат.

`AIZAK_DATASET` позволяет явно указать другой файл. Для конкурсного показа
используйте штатный CSV либо предоставленный организаторами эквивалент.
Путь по умолчанию вычисляется от репозитория и не зависит от текущей папки терминала.
При отсутствии или некорректности файла интерфейс сообщает об ошибке;
подмена неудачного поиска mock-профилями отсутствует.

Поля: `id`, `anon_name`, `categories`, `city`, `price_from_kzt`, `event_formats`,
`languages`, `max_hours`, `busy_dates`, `description`, `synthetic`,
`city_imputed`, `price_imputed`.

Окно календарей: **23.09.2026–31.12.2026**. Вне него доступность неизвестна:
форма не принимает такую дату, backend исключает кандидатов с соответствующей причиной.
`max_hours = null` означает работу без привязки к присутствию, а не ноль часов.
Синтетические профили и восстановленные значения отмечаются в карточках.

## Архитектура и контракт

```text
ui/app.py: форма Streamlit
  → ui/service.py: валидация запроса и адаптер
  → backend.load_profiles(): официальный CSV
  → backend.find_contractors(request, profiles)
  → backend.explanations.add_explanations(): OpenAI или локальные объяснения
  → ui/contracts.py: проверка ответа
  → карточки и объяснение результата
```

Архитектура frontend и backend сохранена. Контракт подробно описан в
[backend/CONTRACT.md](backend/CONTRACT.md) и [ui/INTEGRATION.md](ui/INTEGRATION.md).

```python
from backend import find_contractors, load_profiles

result = find_contractors({
    "city": "Алматы",
    "date": "2026-10-15",
    "event_type": "свадьба",
    "category": "Ведущий",
    "budget": 1500000,
    "hours": None,
    "language": None,
}, load_profiles())
```

Ответ содержит `status`, `message`, `matches`, `excluded`, `more_available`,
`funnel`. У каждой карточки есть `id`, `profile`, `match_reasons`, `warnings`.

Проверяются город, членство в категории, календарь, стартовая цена не выше бюджета,
формат, указанный язык и длительность. Город, категория, формат и язык в backend
сравниваются без учёта регистра; форма передаёт значения из реального каталога.
Порядок воспроизводим: **`price_from_kzt` по возрастанию, затем `id`**.
Это прозрачный ценовой приоритет, а не оценка профессионального качества.

Для каждого исключённого кандидата сохраняются все причины. Один профиль может
не проходить несколько условий; числа причин нельзя складывать как число разных людей.

## Установка и запуск

Нужны Git и Python 3.10+; фактически проверен Python 3.12.14.
Доступ к приватному GitHub-репозиторию необходим для клонирования.

```powershell
git clone https://github.com/BAITC-Hacks/hack-b82ccf3d-aizak.git
cd hack-b82ccf3d-aizak
git switch integration/mvp-hour2
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ui/requirements.txt
.\.venv\Scripts\python.exe -m streamlit run ui/app.py
```

Если используется другая установленная версия Python, замените `py -3.12`
на соответствующий интерпретатор. Откройте локальный адрес, который напечатает
Streamlit (обычно `http://localhost:8501`). API-ключ для этого MVP не требуется.
Если интеграционная ветка ещё не опубликована, сначала необходим её push.

На macOS/Linux аналогичные команды после перехода в ветку:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r ui/requirements.txt
.venv/bin/python -m streamlit run ui/app.py
```

Для явного выбора официального файла в PowerShell при необходимости:

```powershell
$env:AIZAK_DATASET = "C:\path\to\hackathon-dataset-anonymized.csv"
```

## Тестирование

Из корня репозитория, после установки зависимостей:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
.\.venv\Scripts\python.exe -m unittest discover -s ui/tests -v
```

- **13 backend-тестов:** загрузка реальных 66 профилей, CSV/JSONL, фильтры,
  календарь, границы бюджета, язык, часы, три исхода и порядок выдачи.
- **20 исходных frontend-тестов:** форма, проверка контракта, обработка ошибок
  и сверка mock-контракта с настоящим backend. Mock используется явно в тестах.
- **10 новых интеграционных тестов:** настоящая фабрика, официальный CSV,
  реальные карточки и ID, редкая категория, три статуса, смена даты,
  опциональные условия, повторяемость и ошибка загрузки файла.

Проверки не отправляют запросы в AI API. Для frontend используется Streamlit AppTest;
дополнительно проведена проверка работающего сервера в браузере.
Предупреждение AppTest `missing ScriptRunContext` в режиме тестирования не является
ошибкой теста.

## Использование AI и ограничения

**Провайдер — OpenAI**, Responses API; NVIDIA в коде не подключён.
По умолчанию используется `gpt-4.1-mini-2025-04-14`. В первоначальном MVP
провайдер отсутствовал, а OpenAI был указан как план; теперь реализован модуль
`backend/explanations.py`. Формат соответствует
[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

### Настройка ключа

В папке **той версии репозитория, из которой запускается Streamlit**, скопируйте
`backend/.env.example` в `backend/.env` (существующий файл не перезаписывайте).
В `.env` заполните локально строку `OPENAI_API_KEY=`. Ключ не присылайте в чат.
Используется ключ OpenAI API; ключ NVIDIA не подходит этому провайдеру.

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4.1-mini-2025-04-14
AIZAK_AI_ENABLED=true
AIZAK_AI_TIMEOUT_SECONDS=5
```

Переменные окружения имеют приоритет над `.env`, включая пустой ключ и
`AIZAK_AI_ENABLED=false`. Файл ищется только по пути `backend/.env` относительно
модуля, не относительно папки терминала. Поддерживаются простые `KEY=value`,
одинарные/двойные кавычки, комментарии и `export`; подстановка переменных и
многострочные значения не поддерживаются. Ключ перечитывается при новом поиске.
`.env` и `.env.*` игнорируются Git; исключение — безопасный `.env.example`.

### Поведение объяснений

После фильтрации отправляются только выбранные 1–3 кандидата, их структурированные
факты, причины соответствия, предупреждения и условия поиска. Полный каталог,
описания свободным текстом, календари занятости и исключённые профили не отправляются.
Алгоритм, ID, цены, причины исключений и порядок результатов не меняются.
Ответ модели имеет вид `{"explanations": [{"id": "…", "explanation": "…"}]}`;
он сопоставляется по ID в исходном порядке. Повторы, чужие/пропущенные ID,
некорректные тексты, отказ или неполный ответ переключают всю выдачу на резерв.

Нет ключа, AI выключен, неверная настройка, таймаут, ошибка авторизации или лимит API —
карточки продолжают работать с индивидуальными объяснениями из CSV. Источник текста
подписан в карточке. `match_reasons` и предупреждения сохраняются полностью.
Используется один HTTPS-запрос, таймаут сетевой операции 5 секунд (настраивается
в пределах 0.1–8), без повторных попыток, ограничены размер ответа и выходные токены.
Редиректы запрещены, ошибки API и ключи не выводятся в интерфейс или логи.
`store=false` передаётся в запросе; это не утверждение об отсутствии всех журналов
на стороне провайдера. Открытие формы и её перерисовка не вызывают API;
нажатие «Подобрать» с ключом и подходящими кандидатами вызывает API и может расходовать кредиты.

Добавлены 13 backend-тестов конфигурации и AI и 3 проверки Streamlit с mock.
Проверены успешный ответ в обратном порядке, ошибки/таймаут, резервный режим,
неизменность подбора, минимальный payload, отсутствие повторного запроса при
перерисовке и отсутствие сети в обычных тестах. Единственный живой запрос завершился
таймаутом, поэтому качество реального AI-ответа пока не проверено. Автоповтора не было;
отсутствие ответа с usage не доказывает отсутствие списания токенов у провайдера.

Известные ограничения текущей версии:

- Резервные тексты используют имя, цену, формат, языки и часы конкретного профиля.
  Если факты профилей совпадают, они честно повторяются. Структура AI-ответа
  проверяется автоматически, но смысловую точность всех формулировок модельного
  текста это не гарантирует; качество живого ответа ещё не проверено.
- CSV содержит анонимизированные и синтетические данные, восстановленные города и
  цены; это не подтверждённая доступность реального рынка.
- Цена «от» не гарантирует окончательную стоимость, календарь не заменяет бронирование.
- Проверен локальный запуск. Публичный деплой не выполнялся и не требуется в
  предоставленном тексте задания. Для будущего размещения нужны Python-среда,
  зависимости `ui/requirements.txt`, официальный CSV и запуск `ui/app.py` через
  Streamlit; хостинг должен поддерживать WebSocket-соединение Streamlit.
- Готовность этого коммита относится к работающему интегрированному MVP,
  а не к заявлению о выполнении всех критериев конкурсной оценки.
